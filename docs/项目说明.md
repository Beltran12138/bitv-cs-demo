## 一、项目概述

**bitV 智能客服系统**是面向加密货币交易所的生产级 AI 客服机器人，基于多 Agent 架构 + RAG 知识库 + 实时人工接管三合一设计，实现用户问题的**自动解决、兜底转人工、全程可观测**。

| 维度 | 描述 |
|------|------|
| **定位** | 加密交易所 24/7 前线客服，覆盖注册/KYC/充提/交易/安全/合规全流程 |
| **AI 自动解决率** | ~70%（意图命中 + LLM 生成答案） |
| **转人工响应** | <100ms 实时推送至客服工作台 |
| **知识库规模** | 47 篇 FAQ，11 个专业领域 |
| **语言支持** | 简体中文 / 繁体中文 / 英文，会话内实时切换 |
| **部署状态** | 已部署至 Vercel，GitHub Actions CI 自动构建 |

## 二、产品背景与业务目标

### 2.1 背景与痛点

加密交易所客服面临三大核心挑战：

1. **高频重复咨询压占人力**：提币未到账、KYC 被拒、手续费查询等问题占据客服工单的 60% 以上，大量重复劳动消耗人效。
2. **用户等待时间长**：人工客服高峰期等待时间可达 30 分钟以上，严重影响用户体验。
3. **多语言覆盖成本高**：全球用户需要中/英双语以上支持，人工配置成本高。

### 2.2 目标用户

| 角色 | 使用场景 |
|------|---------|
| **普通用户** | 通过聊天窗口咨询账户、充提、交易、KYC 等常见问题 |
| **人工客服** | 通过 Agent Dashboard 接管 AI 无法解决的复杂工单 |
| **产品/运营** | 查看 AI 解决率、意图分布等运营数据，驱动知识库迭代 |

### 2.3 核心业务目标

- **降低重复咨询人工处理率**：目标 AI 自动解决 70% 以上的一线工单
- **缩短用户等待时间**：机器人秒级响应，转人工后实时推送，等待时间 <3 分钟
- **提升客服人效**：人工客服聚焦于高复杂度、高价值的工单，人均处理量提升 ≥40%
- **安全兜底**：自动识别场外诈骗、钓鱼等风险话术，主动推送安全提示

### 2.4 成功指标（OKR 映射）

| 指标 | 基准 | 目标 |
|------|------|------|
| AI 自动解决率 | — | ≥70% |
| 用户平均等待时间 | >30 min | <3 min |
| 用户满意度（👍 占比） | — | ≥80% |
| 知识库覆盖意图数 | 8 个 | 11 个（当前已达） |
| RAG 检索 Faithfulness | — | ≥0.85 |
| 单工单人工处理时间 | — | 降低 40% |

## 四、技术架构

### 4.1 系统架构

```
用户浏览器
    │
    │ POST /api/bot
    ▼
意图分类器 (classifyIntent)
    ├─ safety  → 安全告警回复（不调 LLM）
    ├─ human   → 触发实时转人工
    ├─ no_reply→ 静默（纯表情/标点）
    └─ 领域意图 → RAG 检索
           │
           ├─ [有 OPENAI_API_KEY] DeepSeek 改写查询 → text-embedding-3-small → pgvector 相似度检索
           └─ [无 OPENAI_API_KEY] 意图过滤 FAQ + cross-ref 跨引用补全
                     │
                     ▼
              注入 Top-3 FAQ chunks + 常见追问
                     │
                     ▼
           DeepSeek Chat（11 个专家系统 Prompt）
                     │
              ┌──────┴──────┐
              ▼             ▼
        消息写入 PostgreSQL   Langfuse Trace
              │
     Supabase Realtime 推送
        ├─ 用户聊天页
        └─ 客服工作台
```

### 4.2 技术栈

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| 前端框架 | Next.js 16 App Router + TypeScript | 服务端渲染，API Routes 内置 |
| UI | Tailwind CSS | 原子化样式，无额外组件库 |
| 实时通信 | Supabase Realtime（postgres_changes） | 基于 WebSocket，<100ms 延迟 |
| 数据库 | PostgreSQL via Supabase + pgvector 扩展 | 向量存储与余弦相似度检索 |
| AI 模型 | DeepSeek Chat（OpenAI 兼容 SDK） | 对话生成，兼容 GPT-4 格式 |
| RAG 向量化 | OpenAI text-embedding-3-small（可选） | 生产环境语义检索 |
| LLMOps | Langfuse | LLM 全链路追踪，Trace/Score/Cost |
| 部署 | Vercel | 自动 CI/CD，全球 Edge 网络 |
| 测试 | Jest + ts-jest | 111 个单元/集成测试 |

### 4.3 关键设计决策

| 决策 | 理由 |
|------|------|
| API Key 仅服务端使用 | `DEEPSEEK_API_KEY` 不暴露给浏览器，防止密钥泄露 |
| 两级 RAG 降级策略 | pgvector（生产）→ 意图过滤（Demo/无 Key）→ 兜底转人工，保障响应率 |
| 跨引用知识图谱 | 每条 FAQ 含 `related[]` 字段，intentFilter 自动补全相关页面，提升多领域问题上下文 |
| Supabase Realtime 去重 | 消息按 ID 去重，防止 WebSocket 重连时消息重复渲染 |
| LLM 懒初始化 | Langfuse 实例仅在首次请求时初始化，避免 Next.js 构建期报错 |
| 演示/生产两套路径 | Demo 无需 OpenAI Key 即可运行，降低演示门槛 |

## 八、LLMOps 监控

系统已集成 **Langfuse** 进行全链路 LLM 可观测性追踪。配置 `LANGFUSE_SECRET_KEY` 后自动启用，无需额外代码改动。

### 追踪内容

| 追踪项 | Langfuse 位置 |
|--------|--------------|
| 完整 Prompt（系统指令 + 历史 + 用户输入） | Traces → 展开 Generation |
| LLM 生成回复 | Traces → Output |
| Token 用量（Prompt / Completion） | Model Cost |
| 意图分类结果 / 使用的 Prompt Key | Metadata |
| RAG 检索命中 chunk 数 | Metadata |
| 用户 👍/👎 反馈评分 | Scores（绑定至对应 Trace） |

### Langfuse 接入步骤

1. 在 [cloud.langfuse.com](https://cloud.langfuse.com) 创建免费项目
2. 复制 Public Key 和 Secret Key
3. 填入 `.env.local`：
   ```
   LANGFUSE_PUBLIC_KEY=pk-lf-...
   LANGFUSE_SECRET_KEY=sk-lf-...
   ```
4. 重启开发服务器，Trace 即时可见

> 未配置时系统正常运行，所有 Langfuse 调用为空操作（no-op）。

## 九、RAG 质量评估

### 9.1 Golden Q&A 评估（CI 自动运行）

13 个覆盖全部 11 个意图的 golden 测试用例，在每次 Push 时通过 GitHub Actions 自动执行，无需 API Key，验证：

- **意图分类准确性**：分类器对真实用户查询的意图判断是否正确
- **知识检索命中率**：检索结果是否包含期望关键词

```bash
npm test   # 运行全部 111 个测试，含 golden eval
```

### 9.2 RAGAS 端到端质量评分（手动运行）

端到端评估完整 RAG 流水线质量（需 DeepSeek API Key）：

```bash
DEEPSEEK_API_KEY=sk-... npm run eval
```

输出示例：

```
bitV RAG Eval — RAGAS-style faithfulness + answer relevance

  maker taker费率是多少           intent=fee       faith=0.95  relev=0.92
  账户冻结了怎么解冻              intent=account   faith=0.91  relev=0.88
  ...

AVERAGE                                             0.92        0.90

PASS RAG pipeline quality: GOOD
```

**评分说明：**
- **Faithfulness（忠实度）**：回答是否仅基于检索到的知识，不产生幻觉（目标 ≥0.85）
- **Answer Relevance（相关性）**：回答是否直接解答了用户问题（目标 ≥0.85）
